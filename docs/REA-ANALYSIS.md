# Reference analysis (REA skill)

The feature set of this visualiser was mapped from the public tilesview.ai visualiser using the
[REA – reverse-engineer-anything](https://github.com/morluto/rea) skill (installed in
`.claude/skills/reverse-engineer-anything`, MIT licence). Only public, shipped assets were examined.
No source code, artwork or data from the reference was copied. This project is an independent
implementation with its own code, procedural tile art and 3D rooms.

## How it was analysed

1. The homepage's **"Try Our Visualizer"** button opens a Bootstrap modal containing an iframe:
   `https://tilesview.ai/app/<vendorId>/room-select`.
2. The app shell's public JS bundles were downloaded and analysed with REA's CLI fallback:
   `npx rea-agents analyze-javascript-application <bundle-dir> --json`.
   REA recovered the route map, network endpoint candidates and browser storage keys.
3. The app's public UI string table (`/app/locales/en/translation.json`) was read to list every
   user-facing feature.
4. A live run was attempted with a browser. The app's API answers `403` to automated clients, and
   that protection was respected (not bypassed), so the runtime UI was not observed.

## How the reference renders room photos (static bundle analysis)

Live network capture of a room wasn't possible: the app API answers `403` to automated clients, and
that was respected. The public client bundle shows what the API returns and how it is composited
(technique only; no code copied).

**Room data** (`room_setting_json.room`):
- `room_imgs.ori_img`: the original photo (background)
- `room_imgs.obj_mask`: a server-generated cut-out of foreground objects, drawn on top
- `room_imgs.w_trans`: a cut-out for windows/transparent parts, also drawn on top
- `room_imgs.merger`: a lighting layer drawn over the tiled surfaces
- `objectList[]`: one plane per surface with `position`, `rotation`, `mesh_size`, `tile_size_ratio`,
  `mask_boundaries`, `texture_setting`, `surfacemask_id`, `flipU/flipV`, `mirror` and `foldFrom`

**Camera and planes:** fitted to the photo from `vanishingPoints` and `focal_length`
(`ScreenFitMatrix`). Surfaces are real 3D planes in three.js (`frameloop: "demand"`, soft shadows, stencil).

**Clipping:** a surface-ID mask texture (red channel = surface id). A shader discards pixels of other
surfaces and feathers edges by about 6px.

**Draw order:** photo, then ID-masked tile planes, then lighting layer, then object/window cut-outs
(last), so objects keep their exact original pixels and colours whatever tile is applied.

### How this project matches it

| Reference | This project |
|---|---|
| Vanishing-point camera + 3D planes | 4-corner homography (the same projective mapping for a flat surface) |
| Surface-ID mask, feathered edge | Per-surface mask, feathered edge |
| `obj_mask` / `w_trans` drawn last | **Object layer** drawn last: original photo pixels, untouched |
| Object mask generated by their AI | **Snap-to-object brush**: paint roughly, colour segmentation (GrabCut-style, with a spatial prior) finds the outline |
| `merger` lighting layer | Light factor derived from the photo, normalised to the surface mean |
